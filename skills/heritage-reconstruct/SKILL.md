# 历史建筑复原

把研究依据、空间选择、实际生成与未解决问题一起交付。可以缩小到用户指定的一栋建筑或少量镜头，不强制采用波斯波利斯的规模或图数。

## 先选工作模式

- **已有案例重建**：阅读 [运行工具](references/runtime.md)，对用户指定的 case 先 verify，再在新的输出目录 reproduce。重建模型、展馆和文件包，不把回放图片说成重新生图。
- **新遗址制作**：阅读 [研究到交付](references/workflow.md)，使用自带工具 init 草稿，完成来源与空间准备后再实际生图。

脚本路径是本技能目录的 `scripts/heritage.py`，不依赖本项目仓库。标准库路线需要 Python 3.9+。可选 PNG 栅格渲染另需 NumPy/Pillow，依赖表在 `assets/runtime/requirements-render.txt`。若没有真实可用的生图工具，完成可用准备材料并准确报告生成尚未执行。

## 关键决策

1. 确定地点、主体年代、范围和用途。宫殿核心不等于整座城市；没有平面证据也不代表规模小。主体与跨期细节分别记录。
2. 先查可核验的发掘、博物馆、大学及研究资料。记录实际读过的内容；把来源陈述、自己的推断和未知项分开。不要拿同名晚期建筑或类似遗址的尺寸冒充目标建筑。
3. 用 source / claim / component / scene 编号连接材料。A/B/C/D/UNKNOWN 是本工作流的确定性约定，不是准确率或专家认证。来源的权威程度与某项屋顶、墙高的确定程度分别判断。
4. 在生成前固定主要体量、入口、柱网和机位。粗略注册、模型、地形和完整上部不能称为测绘或 DEM。模型中的正确结构不会自动约束最终图片。
5. 使用当前环境实际可调用的生图工具。为结构、相机、史料与风格输入说明不同角色；只记录实际提交过的提示词与输入。工具不暴露模型/seed 时保留 UNVERIFIED，不猜参数。
6. 保存原生图、尝试与修正链。`record-generation` 只导入真实返回文件，不调用服务、不自动超分，也不证明服务端身份。4K 尺寸与原生 4K 分开记录。
7. 看实际图像并对照依据，检查年代、建筑关系、入口、柱数、人体/动物形态和现代混入物。重点错误要定向修正；保留旧图和残余问题。使用 record-review，无法确认则保留 UNVERIFIED，不用总分抵消关键失败。
8. 在明确展示边界后交付证据、模型、相机、原生/成图、提示词、审核和可打开的展馆。第三方底图单独核对权利，未明确可再分发的材料保留出处而不混入第一方许可。公开发布与全局安装按用户当前授权执行。

## 输出时说明实际完成的范围

分别报告：研究/来源范围、已生成与回放的图、模型检查、实际图像审查、技术验收和未知项。不要声称完整城市、人口、逐像素模型绑定或考古认证，除非有相应证据。

需要快速验证工具本身时，可按 runtime.md 的合成样例运行。那是软件练习，不能用来证明历史复原或 AI 生图已经完成。
