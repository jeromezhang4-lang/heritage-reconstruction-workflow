# 历史复原案例审查

审查用户指定的案例，不仅转述它自带的 PASS。默认不修改案例、不重新冻结它、不发布内容；审核报告写到独立路径。用户授权修复时才进入具体修复工作并保留旧结果。

## 先做可重复检查

自带 `scripts/heritage.py` 和 `assets/runtime/`，需要 Python 3.9+，不要求安装完整仓库。按 [运行工具](references/runtime.md) 对 case 执行 verify / audit，并保存新报告。缺少 manifest、文件或编号应报告具体失败，不用 freeze 掩盖意外变化。

不符合本项目格式的案例，按 [人工审查清单](references/review.md) 进行有范围的审查；不要为了通过工具偷偷重写用户的数据。

## 再检查事实与画面

- 看来源的实际读取范围、年代与原图；区分原始遗存、后世修复、现代展示和类比。来源打不开时保留访问限制，目录不能当全文。
- 追踪有代表性的 source → claim → component / scene → prompt / actual input → result → review。文件哈希证明一致性，不证明历史命题。
- 查看实际图片及重要前后图，检查入口、主要建筑关系、柱网、屋顶、人体/动物解剖、现代混入、人物比例及区域密度。不能只看文字元数据或模型。
- 分开检查模型结构和生成图片；模型柱数正确不能推出可见图片柱数正确。技术回放也不证明完成了新生图。
- 核对原生尺寸、超分说明、服务可见参数和生成/修正链。模型/seed 未暴露时不能补造。
- 保留未知项和剩余错误。审核者自己的观察不自动成为独立考古专家认证；若没有合格专业审查，说明这一限制。

## 报告

先给影响使用/发布的发现，再给证据路径和建议。将结果至少分成：技术完整性、已实际查看的画面、历史依据与推定、未查看/无法验证的项目。标明审核范围和所用文件版本。

对真正错误用 FAIL，对证据不足用 UNVERIFIED，对已执行并通过的具体检查用 PASS。若历史案例保留已知有误的画面作为研究过程证据，应要求醒目标注，不能把它当作已经验收的精确复原。
